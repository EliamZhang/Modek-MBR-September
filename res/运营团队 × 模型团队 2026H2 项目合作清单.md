# 运营团队 × 模型团队 2026H2 项目合作

## 1. 合作背景与目标

围绕运营团队 2026H2 OKR，模型侧重点支持 **Fundo 老客运营、APP 运营、Risk-Based Pricing、WageGo Cross-sell、Campaign 精细化运营及经营分析自动化** 等核心方向。

整体合作目标：

- 在规则运营的基础上，叠加 **风险 × 意愿 × 价值** 驱动的精细化运营能力，建立统一的客户价值评估与人群分层体系；
- 建设触达—归因数据基建，沉淀触达时序、疲劳度与权益组合策略；
- 通过 AI Agent 辅助日常分析、监控与诊断，降低人力投入。

## 3. 项目一：客户价值与人群分层体系

### 业务背景

额度、期限、定价、优惠券、Campaign 成本、Cross-sell 等运营策略，长期来看需要以 **客户长期盈利能力** 作为统一评价标准；同时运营团队已围绕风险、意愿、价值开展差异化 Campaign，三个维度可进一步整合为统一、定期刷新、可直接调用的人群分层体系。

### 1.1 客户 LTV 模型

建立客户长期价值框架：

**LTV = 收入贡献 - 风险损失 - 资金成本 - 获客/运营成本**

重点评估：

- 额度、期限、定价对长期盈利的影响；
- 优惠券/权益投入的 ROI；
- 不同客户群体的长期价值。

应用场景：Fundo 老客额度策略、Risk-Based Pricing、客户权益分配、Campaign 人群选择、高价值客户识别、Cross-sell。

### 1.2 Risk × Intent × Value 人群分层体系

| 维度 | 核心问题 |
| ---- | -------- |
| Risk | 这个客户能不能借？ |
| Intent | 这个客户现在想不想借？ |
| Value | 这个客户值不值得重点经营？ |

形成例如：

- 低风险 × 高意愿 × 高价值 → 核心经营人群
- 低风险 × 低意愿 × 高价值 → 激活人群
- 中风险 × 高意愿 × 高价值 → 定价优化人群
- 高风险 × 高意愿 → 风险控制人群

建设内容：Risk Score 接入、Borrowing / Repay Intent 建模、Value / LTV Score 接入、三维分层规则、人群定期刷新、Campaign 人群包定期输出。

### 1.3 Fundo Score 运营分（P1）

Risk Score 回答「风险高不高」，LTV 回答「长期价值高不高」，Fundo Score 回答「**这个客户当前是否值得运营**」。

输入维度：

- 借贷行为：借款次数、额度、复借频率、还款表现
- APP 行为：登录、页面浏览、Loan Page / Offer 浏览、Push 点击、最近活跃时间
- Campaign 行为：SMS 点击、Email Open / Click、Campaign Response
- 客户价值：Risk、LTV、Intent

输出：统一 **Fundo Operating Score**，支持 Campaign 排序、高潜客户识别、APP 激活、Cross-sell、差异化触达。

### 主要交付物

1. LTV 指标体系、客户级 LTV 标签与预测模型
2. 净收益与 ROI 指标评估体系（支撑策略迭代与资源配置）
3. Risk × Intent × Value 用户矩阵与用户级运营标签
4. 人群定期刷新 Pipeline 与 Campaign 调用接口/数据表
5. 老用户运营应用机制（分层结果落到老客额度、定价、权益策略）
6. Fundo 运营分

## 4. 项目二：Risk-Based Pricing 智能优化

### 业务背景

运营团队已计划开展 Risk-Based Pricing 测试。希望在人工观察实验、调整价格的基础上，逐步增加数据驱动的价格敏感性分析，为定价调整提供量化依据。

### 2.1 价格敏感性分析与 Pricing Matrix 优化

1. **价格敏感性分析**：识别不同用户对价格变化的响应（Apply / Drawdown / Conversion / Repeat / Default / Revenue / LTV）。
2. **敏感性变量挖掘**：风险水平、收入、历史借贷行为、复借次数、APP 活跃度、最近借款时间、借款需求强度、LTV。
3. **Pricing Matrix 优化**：逐步形成 Risk Band × Value Band × Intent Band → 定价建议。

### 2.2 Pricing 迭代机制（P1）

逐步沉淀定价迭代机制：

> Pricing Experiment → Response Modeling → Profit / LTV Simulation → 定价调整建议 → 新一轮实验

### 主要交付物

1. Pricing Test 分析框架
2. 价格敏感性模型与 Pricing Response 曲线
3. Pricing Matrix 优化方案
4. 定价迭代 Prototype

## 5. 项目三：触达与归因数据基建

### 业务背景

用户同时接受 SMS / Email / Push / APP 等多渠道触达，需要解决两个问题：**哪次触达产生了作用**（归因），以及**何时发、多久一次、通过什么渠道、发什么权益**（触达策略）。

### 3.1 多触点归因链路

建立统一事件链路：

**Customer → Touchpoint → Channel → Campaign → Open / Click → APP Visit → Apply → Approval → Drawdown**

统一 customer_id、campaign_id、message_id、channel 及各环节时间戳，形成 **Exposure → Engagement → Conversion** 链路。

### 3.2 触达策略优化（时序 / 疲劳度 / 权益组合，P1）

- **Send Time Optimization**：分析星期、时段、Payday 前后、上次借款后时长、上次 Campaign 后时长对转化率的影响。
- **Contact Fatigue**：研究周期内 SMS / Email / Push 触达次数与 Open / Click / Conversion / Unsubscribe / Complaint 的关系。
- **Offer 权益组合实验**：分析利率折扣、减免券、额度/期限优惠等权益与渠道、时机的组合效果，支撑差异化运营实验设计。

输出：**Customer Contact Policy**（同一客户周期内最大触达次数、渠道最短间隔、分段最优频率）与权益组合实验结论。

### 主要交付物

1. Campaign Event Data Mart、Customer Touchpoint Timeline、Conversion Attribution Table
2. Campaign Funnel Dashboard、多触点归因模型
3. Customer Contact Policy 与权益组合实验结论

## 6. 项目四：运营 AI Agent

### 目标

通过 AI Agent 辅助完成运营分析工作，覆盖 Campaign、AB Test、Email 与竞争流失监控，形成「监控 → 诊断 → 总结 → 推荐」的辅助分析流程。

### 4.1 Campaign & AB Test Agent

- **Campaign Monitor**：定期输出发送量、Delivered / Open / Click / Apply / Drawdown 漏斗、Segment 表现、渠道异常、历史对比等。
- **AB Test Agent**：辅助完成 Experiment Setup → Sample Check → KPI Monitoring → Significance Test → Segment Analysis → Conclusion → Recommendation，输出标准实验报告。

### 4.2 Email IP / Domain Monitor

定期监控 Delivery / Bounce / Spam / Open Rate 与 Domain 表现，辅助定位 Gmail / Outlook / Yahoo 等异常波动。

### 4.3 竞争与流失分析 Agent（P1）

结合 Bank Statement、Loan Transaction、Counterparty、APP 行为、Fundo 借款历史、Campaign 行为，识别「长时间未复借 → 流水出现 MoneyMe / Nimble / Wallet Wizard 等竞品贷款交易 → 竞品迁移」。

输出：流失客户数量与流失率、竞争对手分布、流失客户画像、流失前行为变化、可召回客户名单与召回策略。

## 8. 实施优先级与能力框架

**第一阶段（P0）**：客户价值与人群分层体系、Risk-Based Pricing 分析、Campaign 归因基建、Campaign / AB Test Agent 辅助监控、Email IP / Domain 监控。

解决：**谁值得运营、给谁运营、用什么价格运营、运营效果如何衡量。**

**第二阶段（P1）**：Fundo Score、定价迭代机制、触达时序 / 疲劳度 / 权益组合实验、竞争流失 Agent。

解决：**什么时候运营、怎么运营、客户为什么流失、策略如何迭代。**

最终沉淀为四层能力：

**Layer 1｜Data Foundation**：触达数据 × APP 行为 × 借贷行为 × Bank Statement

**Layer 2｜Customer Intelligence**：Risk × Intent × Value × LTV × Fundo Score

**Layer 3｜Decision Engine**：Audience × Pricing × Channel × Timing × Offer

**Layer 4｜AI Agent**：Monitor × Analyse × Diagnose × Recommend

形成「数据 → 客户理解 → 人群决策 → Campaign 执行 → 实验评估 → 策略迭代」的运营闭环。
